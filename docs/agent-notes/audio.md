# Agent audio — notes d'intégration

État : moteur, bruitages, ambiance, musique par écran, partition générative de manche, lecture du narrateur, page de dev et outils de mesure **faits et vérifiés** (voir §5). Code : `src/host/audio/**` ; page : `dev/audio.html` (`src/dev/audio/**`) ; outils : `tools/audio-*.{mjs,py}` ; fichiers servis : `public/audio/sfx/**`, `public/audio/music/**` (10,0 Mo, budget 20 Mo ; ≈ 98 Mo de PCM une fois tout décodé, les longues pistes étant lues en streaming).

## 1. API d'intégration (phase 3)

Tout passe par `src/host/audio/index.ts`. Rien d'autre à brancher : l'audio s'abonne seul à `simEvents` (bus.ts) et aux volumes de `useSettings`, et lit `gameView` à chaque image dans sa propre boucle `requestAnimationFrame`.

```ts
import { initAudio, preloadAudio, setAudioScreen, setAudioPaused, playUi, playStinger,
         playNarratorLine, preloadNarrator, setAudioListener, audioWingbeat, onAudioUnlock } from './audio/index.ts'

initAudio()                                   // au démarrage (crée l'AudioContext, suspendu jusqu'au 1er geste)
await preloadAudio(p => setLoading(p))        // écran de chargement : 0..1, progression réelle (octets)
setAudioScreen('title')                       // à CHAQUE changement d'écran (voir ci-dessous)
```

| Appel | Quand | Effet |
|---|---|---|
| `setAudioScreen(s)` | `'loading' \| 'title' \| 'lobby' \| 'intro' \| 'round' \| 'roundResults' \| 'gameResults' \| 'credits'` | musique de l'écran (fondus enchaînés), ambiance, profil des bruitages. En manche, la partition générative suit toute seule `gameView.sim` (compte à rebours compris) ; la nuit la coupe net. |
| `setAudioPaused(b)` | pause / reprise | musique étouffée (passe-bas 400 Hz, −8 dB). **La ponctuation (harpe) n'est plus jouée ici** (elle l'était deux fois) : l'appelant joue `playStinger('pause' \| 'resume')`. La partition suit le temps de simulation : elle s'arrête d'elle-même si la simulation est figée. |
| `playUi(name, { colorIndex?, value? })` | UI du PC | `hover`, `click`, `confirm`, `back`, `error`, `toggle` (value 1/0), `open`, `close`, `slider` (value 0..1), `join` / `leave` / `botAdd` (colorIndex : la note du joueur), `botRemove`, `ready` (colorIndex facultatif), `unready`, `launch`, `count` (décompte des %, value 0..1), `sun` (soleil qui vole vers un nom, value = rang 0..). |
| `playStinger(name, { colorIndex? })` | temps forts hors manche | `roundWin` (au dévoilement du vainqueur de manche), `gameWin` (podium), `lastRound` (annonce de la manche × 2), `pause`, `resume`, `rematch`. |
| `playNarratorLine({ lineId, colorIndex?, lang? })` | le directeur (src/director) a choisi une réplique | joue `public/audio/narrator/<lang>/<lineId>[.<colorIndex>].mp3` si le manifeste le connaît et que le réglage vaut `'voice'`, avec ducking (musique, ambiance et interface −6 dB, bruitages −5 dB, creux de −4 dB à 2,5 kHz sur le monde ; 80/400 ms) ; publie le sous-titre sur `subtitleEvents` (bus.ts) si le réglage vaut `'voice'` ou `'text'` ; rien si `'off'`. Renvoie `{ shown, voiced, duration, done }`. Une nouvelle réplique coupe la précédente (fondu 60 ms), **sauf s'il reste moins de 0,8 s de voix** : elle attend alors sa fin. Le `hide` part à la fin prévue de l'affichage ou, si la voix sonne encore (horloge audio en retard), à la fin réelle de la voix. |
| `preloadNarrator(lang, colorIndices)` | au lancement d'une partie | décode à l'avance les voix des couleurs présentes. |
| `setAudioListener({ x, y, halfWidth, halfHeight } \| null)` | caméra (chaque image, facultatif) | cadre visible en mètres monde : panoramique des bruitages (−0,8..0,8) et atténuation hors cadre. Sans appel, l'audio estime ce cadre depuis les oiseaux et leurs ombres (GDD §13.1). |
| `audioWingbeat(slot, force01)` | rendu des oiseaux (facultatif) | battement d'aile synchronisé sur le coup d'aile vers le bas de l'animation ; sans appel, l'audio estime le rythme depuis la vitesse de montée. |
| `onAudioUnlock(cb)` / `isAudioUnlocked()` | UI | le navigateur n'autorise le son qu'après un geste (clic, touche) : l'UI peut afficher une invite discrète tant que ce n'est pas fait. Les pistes bloquées repartent seules (avec fondu) au déverrouillage. |

**Sous-titres** (`subtitleEvents`, `src/host/bus.ts`) : `{ type: 'show', id, lineId, text, parts, colorIndex?, lang, durationMs, voiced }` puis `{ type: 'hide', id }`. `parts` isole le nom de couleur (`{ text, colorIndex }`) pour la pastille et l'encre du récitatif. L'UI peut se fier à `hide` ou à `durationMs`.

**Runner** : rien à faire de plus que publier les événements (`simEvents.emit`) et tenir `gameView` à jour (`sim`, `alpha`, `timeScale`, `players`). La musique se cale sur `sim.sun.t` interpolé par `alpha`, et ralentit avec `timeScale` (ralentis de touche, dernière seconde à 0,5×) ; le monde sonore s'étouffe pendant les ralentis (passe-bas sur musique + ambiance + bruitages, pas sur l'UI ni la voix).

## 2. Ce qui sonne, et quand

- **Bus** : musique, ambiance, bruitages, interface, voix → maître (compresseur doux, limiteur à −4 dB, saturation douce plafonnée à −0,5 dBFS). Volumes du réglage : courbe quadratique ; l'ambiance suit le curseur « effets ». Une seule réverbe (convolution générée, 2,8 s, entrée mono) pour musique et bruitages ; ses envois copient volumes, ducking et pause.
- **Bruitages** (`sounds.ts`, `sfx.ts`) : chaque son est réglé en **sonie perçue** (LUFS momentanés mesurés sur le fichier encodé, `manifest.gen.ts`), avec variations sans répétition immédiate, hauteur et volume aléatoires, polyphonie par son, temps de garde. Table événement → sons : compte à rebours (bâtons de bois qui montent, conque + cloche tibétaine en la à « Envol »), phases (carillon réaccordé en la pentatonique), Grande Ombre (boum + trémor), « dix secondes » (bol tibétain réaccordé en la), 5 dernières secondes (bloc de bois qui monte), nuit (coupure : plus aucun bruitage d'oiseau, le vent tombe d'un coup, 1,5 s de silence, gong en la, puis les grillons), prise d'élan (cri de buse ralenti de 5 demi-tons + repli des ailes), chute guidée (grand souffle qui suit l'oiseau et s'aiguise, plus un **sifflement** généré — bruit en bande étroite dont la hauteur monte avec la vitesse), clac (généré : double claquement boisé), engagement (« boum » de plumes d'engoulevent, qui culmine vers l'impact), touche (punch + chute + plumes + cri de la victime + accord de l'harmonie courante joué par la partition ; couronne : + sub + cloche), raté (choc + sable), esquive (souffle + « ting » si humain), feinte, coup d'aile (battement lourd + souffle), battements de montée (rythme selon la vitesse de montée, 6 voix max), collisions (oiseaux : choc mou + plumes ; tour : choc + frottement), « tsk » (généré : crépitement granuleux), verrouillage (tic, humains seulement), coup d'aile rechargé (tic, humains), caché (souffle étouffé, humains), Simoun (rafale), couronne (cloche en la ; la note du nouveau meneur est jouée en rythme par la partition), gros vol (sub + sable ; la nappe fait un « trou » d'un temps), remise à zéro du lobby (sablier). Écran titre : bruitages à −12 dB, sans signaux de manche ; salon : −10 dB (cartes des règles : −18 dB), et entre bots, ni cri de victime, ni culbute, ni « boum » de piqué, ni gros vol. **Hiérarchie (polish A4)** : sons de « lit » (coup d'aile, son souffle, battements de montée, piqué qui descend, « tsk », tours) à −5 dB pour un bot, et −10·log10(n/6) dB au-delà de 6 oiseaux ; « tsk » plafonné à 3/s ; un bot hors cadre ne joue pas ses battements de montée ; 24 voix au plus dans la Grande Ombre (les signaux `essential` et l'interface passent toujours). **Accents (A7)** : couronne +4 dB, gros vol +3/+4 dB, dix secondes +3 dB, esquive +4 dB, chacun avec un creux de musique de −3 dB (200-250 ms, `engine.dipMusic`). Les 5 dernières secondes sont jouées par la partition sur le battement de cœur le plus proche (`RoundMusic` → `sfx.lastSecond`). Nuit : `engine.silenceWorld(1,4 s)` + toutes les couches d'ambiance à zéro 1,3 s (vrai silence), puis gong et grillons.
- **Note de chaque couleur** : A3 C4 D4 E4 G4 A4 C5 D5 E5 G5 A5 C6 (la mineur pentatonique, tongue drum) pour les couleurs 0..11 — rejoindre, prêt, nouveau meneur, victoire.
- **Ambiance** (`ambience.ts`) : vent de base ; vent d'altitude (altitude et vitesse moyennes) ; vent procédural : corps (bruit rose, bande qui « respire »), **vent aigu** proportionnel aux oiseaux hauts, **souffle grave** aux oiseaux bas ; vent chantant (épines de cactus d'Atacama) qui s'installe à l'heure dorée ; hurlement pendant la Grande Ombre ; grondement du front de nuit panoramiqué à sa position ; grondement du Simoun à la position des oiseaux dedans ; **grain de sable** (bâton de pluie + grains générés) ∝ m²/s réellement peints (`paintedCells` de la simulation : médianes mesurées 1 900 m²/s à midi → 3 150 dans la Grande Ombre) ; grillons à la nuit et aux résultats ; carillon généré au salon (lames FM en sol pentatonique, une à trois toutes les 3-8 s ; l'ancien `amb_chimes_loop` sonnait en fa −24 c et a été retiré) ; rafales au hasard ; cris lointains à l'écran titre. Les couches silencieuses sont arrêtées et détachées.
- **Musique** (`music/`) : titre = Zhelanov *Futuristic ambient 1* (CC-BY, streaming, départ à 13 s et +2 dB : l'intro du fichier est quasi muette) ; lobby et règles = isaiah658 (boucle de 24 s en sol majeur, compatible avec les notes de join ; un passage sur deux plus sourd, −2,5 dB et passe-bas 1,9 kHz, cycle de 49 s) ; résultats de manche = cynicmusic *Synthwave 4k* (chaque écran de résultats repart d'une autre section : 0 / 44 / 90 / 22 / 67 s) ; les sons d'interface accordés (pluck, notes de joueur) montent d'un demi-ton sur l'écran titre (mi♭ mineur) ; podium = cynicmusic *Lifewave 2k* (intro muette sautée) ; crédits = Tri-Tachyon *Dust* (CC-BY). Fondus enchaînés 2,5-4 s ; après une manche, la piste des résultats attend 1,2 s (le gong respire).
- **Partition de manche** (`music/score.ts`, `tempo.ts`, `instruments.ts`, `synth.ts`) : la mineur, ~84 BPM **calé pour qu'« Envol » et le début de la Grande Ombre tombent sur des premiers temps** (34 mesures à 83,3 BPM pour T = 110). Midi : bourdon (tanpura réaccordé) + nappe Am9 ↔ Fmaj7♯11 + cloches de verre ; après-midi : + mélodie au tongue drum (motifs A A' B A'' tirés par manche, dernière note sur l'accord) ; heure dorée : + percussions (tambour sur cadre, tom, shaker, bois), oud en ostinato 3-3-2, complainte de duduk, cadence VI–VII–i ; couchant : + séquenceur « cordes » en doubles croches (Tangerine Dream), cordes aiguës, harmonie tendue jusqu'à E7sus4♭9, souffle inversé qui aspire vers la Grande Ombre ; Grande Ombre : braam, 2/4, pédale de la Am ↔ B♭/A, tutti, **cœur 1 → 2 Hz** (le tempo EST le cœur : nombre de temps entier, la nuit tombe sur un premier temps), montée de bruit ; nuit : coupure en 25 ms (sons directs ET envois de réverbe). T = 80 / 110 / 150 : tout se met à l'échelle. Deux variantes d'harmonie par section tirées à la graine de la manche.

## 3. Décisions (et pourquoi)

1. **Partition générative en WebAudio natif, pas en Tone.js** (écart assumé à D23). Mesuré (`tools/audio-render.mjs --bench`, rendu hors ligne de 10 s) : 5 voix `Tone.Synth` « fatsawtooth » = 3,1 s de calcul contre 0,36 s pour les 15 oscillateurs natifs équivalents ; `Tone.Chorus` 0,55 s, 6 `Tone.Filter` 0,48 s — Tone garde des nœuds qui tournent en permanence (signaux, LFO). Et `Tone.PolySynth` diffère ses notes par `setTimeout` (placement approximatif, inutilisable hors ligne). Les voix natives (`synth.ts`) sont créées à chaque note et libérées à la fin : coût nul au repos, placement à l'échantillon, rendu hors ligne identique. Tone reste installé (utilisé seulement par le banc d'essai de la page de dev).
2. **Tempo exprimé en temps de soleil** : la musique suit la simulation (ralentis, reprise, rafraîchissement du PC) via une horloge à verrouillage de phase (`clock.ts`) et une programmation anticipée de 140 ms.
3. **Sonie perçue partout** : le build (`tools/audio-build.py`) mesure chaque fichier encodé (BS.1770) ; la table des sons donne des cibles en LUFS, pas des gains. Réglé sur une manche jouée par la VRAIE simulation et 6 bots (`--real`) : bruitages ≈ −23 LUFS intégrés (le « tsk » y est l'événement le plus fréquent : ~400 par manche, donc discret), musique de −26 (midi) à −18 (Grande Ombre), ambiance ≈ −28 → −25 ; couches de la partition équilibrées une à une (`tools/audio-stems.mjs`).
4. **Justesse** : échantillons mesurés (FFT, HPS) et réaccordés par rééchantillonnage au build. Tanpura « en mi » : Sa mesuré 80,87 Hz (mi1 −33 c, pas 280 Hz : c'était un partiel) et Pa 120,9 Hz → ×110/80,87 = la2/mi3. Duduk « C3 » = do4 réel. Tongue drum juste à ±2 c (passe-haut à 75 Hz contre un ronflement à 46 Hz). SFX tonals ramenés en la mineur / do majeur : cloche tibétaine (la♯4+45 c → la4), bol (do♯4 → la3), bol doux (fa4 → la4), carillon de transition (mi majeur pent. → do majeur pent.), harpes, cloches des résultats (la majeur → do majeur, comme la musique des résultats), gong court (→ la2). Le gong de la nuit est déjà en la (la2 +9 c).
5. **Interface organique** (bois, papier, verre, tongue drum) plutôt que les bips synthétiques de Kenney : cohérent avec la ligne claire ; les sons tonals d'interface sont en la.
6. **Formats** : OGG Vorbis (PC hôte : Chrome, Edge, Firefox). Musique q0-q2, ambiances q0, bruitages q3. Pas de MP3 : voir §4. Boucles d'ambiance raccourcies à 14-26 s (re-bouclées par fondu) et en mono quand la couche est diffuse ou panoramiquée : une minute stéréo décodée pèse 21 Mo.
7. **AudioContext à 44,1 kHz, latence « balanced »** : tous les fichiers sont à 44,1 kHz (décodage sans rééchantillonnage, ~8 % de calcul et de mémoire en moins qu'à 48 kHz) ; « balanced » plutôt qu'« interactive » : −17 % de CPU mesuré sur le thread audio pour une latence de quelques dizaines de ms, imperceptible à distance de la TV (surcharge possible : `?audioLatency=interactive`).
8. **Coût CPU** : chaque nœud relié coûte, même silencieux. Le graphe de la partition n'est relié au bus musique que pendant une manche ; les couches d'ambiance muettes sont arrêtées et détachées ; automatisations « finies » (rampes linéaires, pas de `setTargetAtTime` sans fin ; un biquad automatisé recalcule ses coefficients à chaque échantillon) ; une seule réverbe ; voix réduites dans la Grande Ombre.

## 4. Limites connues

- **Safari hôte** : pas d'OGG garanti ⇒ le PC hôte doit être Chrome, Edge ou Firefox. (Le téléphone ne joue aucun son de ce module.) Si besoin : réencoder en M4A/MP3 avec `tools/audio-build.py` (≈ +11 Mo).
- **Coût CPU** (`tools/audio-cpu.mjs`, thread de rendu WebAudio de Chrome sur cette machine partagée, charge ≈ 6,5 sur 12 threads) : repos 2 %, titre 18 %, lobby 25 %, manche 30 % (compte à rebours) → 39 % (midi) → 51 % (heure dorée) → 58 % (Grande Ombre), résultats 22 % d'un cœur. Étalon mesuré dans les mêmes conditions : 20 chaînes oscillateur + filtre + gain = 12 % ; la manche vaut donc 3 à 4,5 étalons. Mesures gonflées par la contention (autres agents, TTS) : à remesurer machine calme avec `tools/audio-cpu.mjs`. Le thread audio est indépendant du rendu (pas d'impact direct sur les 60 i/s).
- **Mémoire** : ≈ 98 Mo de PCM décodé (ambiances 46, bruitages 29, échantillons 13, boucle du lobby 9) ; les pistes longues sont en streaming.
- Rien n'a été écouté : tout est vérifié par la mesure (§5). Un passage d'écoute humaine reste souhaitable pour le goût (notamment le « tsk », le « clac » et les cris).
- Les pistes longues rebouclent par fondu de 4 s (deux `<audio>`), pas à l'échantillon.

## 5. Vérification (méthode, reproductible)

- **Page `dev/audio.html`** (`http://localhost:8804/dev/audio.html`) : chaque son, chaque événement de simulation, écrans et fondus, manche jouée par la vraie simulation + bots (ou factice) avec curseur de temps et accès direct aux phases (les couches de la partition entrent sous l'oreille), ralenti de touche, mixeur des bus et des 13 couches (muet/solo), vumètres et spectre, narrateur + sous-titre, rendu hors ligne mesuré avec export WAV.
- `tools/audio-build.py` : construit `public/audio/**` et `manifest.gen.ts` (mesures sur les fichiers encodés), `--credits` imprime la section crédits.
- `tools/audio-analyze.py` : `stats` (crête, RMS, LUFS intégrés et momentanés), `pitch` (justesse), `loop` (couture des boucles : toutes OK), `sheet` (planches enveloppe + spectrogramme), `report` (rendu d'une manche : sonie dans le temps, crêtes, **clics isolés** — détecteur validé sur signal synthétique : saut de phase et impulsion détectés, attaque de shaker ignorée —, chroma par section).
- `tools/audio-render.mjs [--real] [--buses=…] [--mute=…] [--from= --seconds=] [--analyze]` : rend une manche complète hors ligne (OfflineAudioContext, programmation progressive par suspend/resume) avec le vrai système audio, piloté par la simulation factice ou la **vraie simulation + 6 bots** ; exporte WAV + rapport. `--bench` / `--calibrate` : bancs de coût et calibration des couches générées.
- `tools/audio-cpu.mjs` : coût CPU réel du thread audio de Chrome par écran / phase (`--probe=round:99`, `--disable=…`, `--experiment=…`, `--latency=…`), avec recensement des nœuds reliés.
- `tools/audio-flow-check.mjs` : parcours temps réel titre → lobby → manche → résultats → podium → crédits, niveaux par bus.
- `tools/audio-narrator-check.mjs` : voix, sous-titre, ducking (mesuré −6 dB), modes texte et off.
- `tools/audio-stems.mjs --from=60 --seconds=10` : sonie de chaque couche de la partition seule (réglage du mixage).
- `tools/audio-verify.mjs` : tout ce qui précède d'un coup (≈ 10 min).
- **Résultats de référence** (manche T = 110 jouée par la vraie simulation + 6 bots, tous bus, réglages par défaut) : mixage −18,8 LUFS intégrés, crête −1,2 dBFS ; par section compte à rebours −23, midi −19,4, après-midi −19,7, heure dorée −19,0, couchant −17,8, **Grande Ombre −15,5**, nuit −28,6 LUFS (silence de 1,5 s à −34 dB RMS puis gong). Musique seule : −26 (midi) → −18 (Grande Ombre), **aucun clic** ; les 3-5 « clics » du mixage sont des sons voulus (bâtons, tic de verrouillage, « tsk »), vérifiés un à un contre le journal d'événements. Tonalité : 70-81 % de l'énergie de la musique sur la mineur pentatonique (le reste : notes des accords modaux, fa, si, si♭). Boucles : toutes sans couture (saut < 0,3 × le 99,9ᵉ centile, flux spectral ≈ médian). Narrateur : voix jouée, sous-titre publié, ducking mesuré 0,501 (−6,0 dB) puis retour à 1 ; texte seul et off conformes. Captures : `shots/audio/verify_round.png`, `shots/audio/dev_round.jpg`, `shots/audio/narrator_subtitle.jpg`.

## 7. Polish (correcteur audio, 2026-09-26)

Détail, mesures et preuves : `docs/polish/fix-audio.md`. Ce qui change pour les intégrateurs :

- **Graphe** : `buses.sfx → sfxDuck`, `buses.ui → uiDuck`, `buses.music → duckMusic → musicDip → …`, `world → voiceEq (cloche 2,5 kHz) → slowmoFilter`. Pour enregistrer un stem « après ducking », brancher `sfxDuck` / `uiDuck` / `slowmoFilter` (monde traité) plutôt que les bus.
- `AudioEngine.duck()` baisse aussi bruitages (−5 dB), interface (−6 dB) et creuse le monde à 2,5 kHz (−4 dB) ; la voix est à −2 dB du curseur. `engine.ducking` (lecture), `engine.dipMusic(db, s)`, `engine.silenceWorld(s)`.
- `setAudioPaused()` ne joue plus la harpe : `playStinger('pause' | 'resume')` à part (le runner le fait déjà).
- `SoundDef.essential` : jamais refusé par `maxTotalVoices` (24 dans la Grande Ombre, 48 sinon).
- `MusicDirector(engine, getView, onLastSecond?)`, `RoundMusic(engine, onLastSecond?)`, `RoundMusic.drivesLastSeconds`, `Track.start(fade, delay, startAt?)`, `RESULTS_STARTS` (tracks.ts), `Instruments.setLift(db, when, s)` (relief de midi et d'après-midi, +4 dB, `score.ts EARLY_LIFT_DB`).
- `SfxSystem.setScreen(screen)` (appelé par `AudioSystem.setScreen`), `sfx.lastSecond(n, when)`, `sfx.scoreKeepsTime`.
- Nouveaux fichiers : `whoosh_flap_01..03`, `whoosh_down_01`, `whoosh_hide_01` (CC0, `tools/audio-build.py`, `docs/CREDITS-sources.md`) ; `amb_chimes_loop` retiré.

## Polish vague 2 — Edit ciblé du correcteur tech (fuite, détail : docs/polish/fix2-tech.md)

- `music/tracks.ts` : les lecteurs de flux (`<audio>` + `MediaElementAudioSourceNode` + gain) viennent d'une réserve
  par moteur (`takeVoice` / `releaseVoice`). Chrome garde en vie une `MediaElementAudioSourceNode` (et son élément)
  tant que le contexte audio existe, même débranchée : deux par piste jouée s'accumulaient (+14 par cycle de trois
  parties). Maintenant 4 `<audio>` pour toute une session. La minuterie de fin de fondu enchaîné ne met plus en pause
  un élément déjà rendu à la réserve (`!this.stopped`).
